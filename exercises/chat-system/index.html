Chat System — Requirements Exercise

Design brief: Design a real-time messaging service that supports one-to-one and group conversations across web and mobile clients.

Functional Requirements

  • Users can send and receive one-to-one text messages in real time.
  • Users can create group conversations and exchange messages with up to 500 members per group.
  • The system must deliver messages to online recipients immediately and queue them for offline recipients until they reconnect.
  • Users can see per-message delivery states: sent, delivered, and read.
  • Users can see presence indicators (online, offline, last-seen) and typing indicators for their contacts.
  • Users can send media attachments (images, video, files) alongside text messages.
  • The system must preserve and display full conversation history in chronological order.
  • Users can search their message history by keyword and by contact.
  • Users can edit or delete their own sent messages, with the change reflected for all participants.
  • The system must support push notifications to mobile devices for new messages when the app is backgrounded.
  • Users can be authenticated and can maintain multiple concurrent sessions across devices.
  • Messages must be synchronized consistently across all of a user's logged-in devices.

Non-Functional Requirements

  • The system must support 50 million daily active users and 500,000 concurrent connections at peak.
  • End-to-end message delivery latency should be under 500 ms for online recipients (p99).
  • Availability target of 99.99% for message send and receive paths.
  • Messages must be durably stored with no loss once acknowledged as sent.
  • Message ordering within a conversation must be preserved for all participants.
  • The system must sustain a peak throughput of 1 million messages per second.
  • Message content should be protected in transit and at rest to meet privacy expectations.
  • The system must scale horizontally as user and message volume grow, without downtime.
  • Storage and delivery costs should remain efficient as history accumulates over years.

Assumptions & Out of Scope

  • Assume users are already registered; account signup and contact discovery flows are out of scope.
  • Voice and video calling are excluded; only text and media messaging are in scope.
  • Assume clients have intermittent connectivity and may go offline for extended periods.
  • Content moderation and spam detection are out of scope for this exercise.
  • Payments, stickers marketplace, and bot integrations are excluded.
