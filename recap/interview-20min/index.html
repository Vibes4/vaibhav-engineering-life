⚡ 20-Minute Interview Recap Cheat-Sheet

20 minutes is just enough to refresh your brain — not to learn new things. This is the highest-ROI sweep across the stack you'll actually be asked about: Node, Angular, SQL, ORMs, Docker, microservices, plus the soft-but-scored stuff (clean code, testing, CI/CD). Skim the headers, expand whatever feels rusty.

1 · Node.js & Backend

Event loop

  • JavaScript runs on a single thread; async I/O is offloaded to the libuv thread pool or the OS.
  • The loop cycles through phases, and microtasks drain between every phase.
Phases:                         Priority (drains first → last):
1. Timers (setTimeout/Interval)   process.nextTick()
2. Pending callbacks              Promise.then()   (microtasks)
3. Idle / Prepare                 setTimeout()
4. Poll (I/O)                     setImmediate()
5. Check (setImmediate)
6. Close callbacks
One-liner: "Node is single-threaded for your JS, but I/O is concurrent because libuv and the OS do the waiting. nextTick and resolved promises always run before the next timer or I/O callback."

3 · SQL & PostgreSQL

Joins

INNER JOIN   rows matching in both
LEFT JOIN    all left + matches
RIGHT JOIN   all right + matches
FULL JOIN    everything, matched or not

Indexes

Speed up SELECT / WHERE / ORDER BY / JOIN. Don't index low-cardinality columns (e.g. a boolean) or frequently-updated columns — the write cost outweighs the read gain.

EXPLAIN ANALYZE

EXPLAIN ANALYZE
SELECT ...;

Reveals Seq Scan vs Index Scan, estimated cost, and actual execution time. A surprise Seq Scan on a big table is your cue to add an index.

Query optimization

Avoid SELECT * → select only the columns you need (SELECT id, name). Then lean on indexes, LIMIT, pagination, proper JOINs, and batching instead of N+1 queries.

Transactions — ACID

Atomicity · Consistency · Isolation · Durability.

Serializablestrongest — as if transactions ran one at a time

4 · ORM (TypeORM)

Benefits: entity mapping, migrations, relations, and a Query Builder.

Know when NOT to use it: complex reporting and analytical queries → drop to raw SQL. An ORM is for CRUD and relations, not for hand-tuned 6-way reporting joins.

🎯 Questions they may ask — with the angle to take

Explain the Node.js event loop.

Single thread runs your JS; libuv/OS handle I/O concurrently. Phases: timers → pending → poll → check → close. Microtasks (process.nextTick, resolved Promises) drain between phases, so they run before the next timer/I/O callback.

How does Angular's dependency injection work?

Hierarchical injectors. Providers register a token; classes marked @Injectable are requested via the constructor. Angular walks the injector tree (component → module → root) to resolve, which makes services swappable and testable.

How did you optimize a slow SQL query?

Ran EXPLAIN ANALYZE, spotted a Seq Scan on a large table, added the right index, removed SELECT *, added pagination/LIMIT, and rewrote the join. Verified the plan flipped to an Index Scan and latency dropped.

What indexes have you created in PostgreSQL?

B-tree indexes on foreign keys and frequent WHERE columns, composite indexes ordered equality → range → sort (ESR), and partial indexes for hot subsets. Avoided indexing low-cardinality or frequently-updated columns.

Why PostgreSQL over MongoDB?

The data was relational with strong consistency needs — joins, ACID transactions, and complex queries. Postgres gives that out of the box; forcing it into documents would have meant reinventing joins in application code.

Explain your CI/CD pipeline.

Push → build → lint → unit tests → build Docker image → deploy → health check. A failing lint or test blocks the merge; the health check gates the release so a bad deploy rolls back.

Describe a challenging bug you fixed.

Use STAR: the symptom, how you reproduced it, how you isolated the root cause (logs/metrics/bisect), the fix, and the regression test you added so it can't return. Pick a real one with a concrete root cause.

How do you write unit tests in NestJS?

Jest with Test.createTestingModule, mocking providers/repositories so nothing hits a real DB or network. Follow AAA and cover success, failure, and edge cases.

How have you used Docker in development?

A Dockerfile per service and docker compose for local dev (app + Postgres + Redis), giving the same environment across dev/CI/prod and clean isolation.

Explain your microservice architecture.

Services split by domain boundary, each independently deployable with its own data. Sync calls over REST, async events over Kafka/RabbitMQ. Be honest about the costs: network latency, distributed transactions, and monitoring overhead.

Difference between PUT and PATCH?

PUT replaces the whole resource and is idempotent. PATCH applies a partial update. Sending only the changed fields → PATCH; sending the full object → PUT.

How do you prevent SQL injection?

Parameterized queries / prepared statements (or the ORM's bound parameters) — never string-concatenate user input into SQL. Add least-privilege DB users and input validation as defense in depth.

JWT vs session authentication?

Sessions store state server-side and hand the client a cookie id — easy to revoke, needs shared session storage to scale. JWTs are stateless signed tokens — scale horizontally with no lookup, but are hard to revoke before expiry (mitigate with short TTL + refresh tokens).

How do you handle database transactions?

BEGIN … COMMIT/ROLLBACK, or the ORM's transaction wrapper so all writes commit or none do. Pick the isolation level for the consistency you need and keep transactions short to avoid lock contention.

What happens when an API receives 10,000 concurrent requests?

Node's event loop handles the I/O concurrency, but one process has limits. Scale horizontally behind a load balancer, use DB connection pooling, cache hot reads, push heavy work to a queue, and apply backpressure / rate limiting so you degrade gracefully instead of falling over.

Strengths to lean into: Node.js/NestJS backend · Angular + TypeScript enterprise frontend · PostgreSQL tuning & TypeORM · Docker / Kubernetes / microservices · shipping scalable products (e.g. an IAM/OIDC server, a workflow platform).
On AWS, be honest: say you've worked primarily with containerized deployments and know AWS fundamentals (EC2, RDS, IAM, S3) — rather than overstating production depth. Interviewers reward accuracy; getting caught exaggerating is a remarkably inefficient career strategy.
