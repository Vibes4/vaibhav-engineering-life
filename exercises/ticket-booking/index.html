Ticket Booking — Requirements Exercise

Design brief: Design a service that lets users browse events and book seats or tickets that have limited availability.

Functional Requirements

  • Users can browse and search events by name, category, venue, date, and location.
  • Users can view real-time seat or ticket availability for a selected event.
  • Users can select specific seats or a quantity of general-admission tickets.
  • The system must temporarily hold selected seats for a user while they complete checkout.
  • The system must prevent two users from booking the same seat (no double-booking).
  • Users can complete a booking by paying, and receive a confirmation with ticket details.
  • The system must release held seats automatically if a user does not complete payment within the hold window.
  • Users can cancel a booking and, where eligible, receive a refund.
  • Users can view their booking history and upcoming tickets.
  • Organizers can create events and configure seating layouts, capacity, and pricing tiers.
  • The system must issue verifiable tickets that can be validated at venue entry.

Non-Functional Requirements

  • The system must handle sudden spikes of 100,000 concurrent users during high-demand on-sale events.
  • Seat availability reads should return in under 300 ms (p99).
  • Availability target of 99.95% for browsing and booking paths.
  • Seat allocation must be strongly consistent so that a seat is sold to exactly one buyer.
  • Booking and payment records must be durable and must survive component failures.
  • The system must sustain high booking throughput without overselling capacity.
  • Held-seat expiry and inventory release must be reliable and timely.
  • Payment and personal data must be protected in transit and at rest.
  • The system must scale to support many concurrent events across regions.

Assumptions & Out of Scope

  • Assume payment processing is handled by an external gateway integrated by the system.
  • Assume users are authenticated; account registration flows are out of scope.
  • Dynamic surge pricing and resale marketplaces are excluded for this exercise.
  • Venue physical access hardware integration is assumed available and out of scope.
  • Marketing, promotions, and discount-code engines are out of scope.
