AWS — one-liners

QuestionAnswer in one line
Lambda vs Fargate vs EC2Spiky/event-driven → Lambda; steady always-on → Fargate; OS control or licensing → EC2.
Lambda hard limits15-min timeout, 10 GB memory, 512 MB–10 GB ephemeral /tmp, 6 MB sync payload, 1,000 default concurrency.
Cold start fixSmaller bundle, init at module scope, more memory (= more CPU), provisioned concurrency for known peaks.
Reserved vs provisioned concurrencyReserved = guaranteed and capped slice of account limit; provisioned = pre-warmed environments, no cold start.
Lambda + RDS problemConnection exhaustion → RDS Proxy, reserved concurrency, connection at module scope.
SQS vs SNSSQS = one message, one consumer, pull, durable. SNS = one message, all subscribers, push, no retention.
Best fan-out patternSNS/EventBridge → one SQS queue per consumer → workers. Broadcast plus per-consumer durability and DLQ.
EventBridge vs SNSEventBridge adds content-based routing rules, schema registry, SaaS/AWS event sources, scheduling.
Kinesis vs SQSKinesis = ordered, replayable, multiple independent consumers with their own offsets. SQS = delete-on-process, no replay.
Visibility timeoutHow long a received message is hidden. Shorter than processing time → duplicate concurrent processing.
DLQQueue for messages failing maxReceiveCount times. Always alarm on depth > 0.
Exactly-onceDoesn't exist. At-least-once delivery + idempotent consumers via a conditional write to a dedup store.
Dual-write problemDB write + publish aren't atomic → transactional outbox, or DynamoDB Streams as the outbox.
SG vs NACLSG = stateful, ENI-level, allow-only. NACL = stateless, subnet-level, allow and deny; must open ephemeral ports.
Public vs private subnetPublic = route 0.0.0.0/0 → IGW. Private = route to NAT Gateway. Isolated = no internet route at all.
NAT Gateway riskOne per AZ or an AZ failure kills egress everywhere; costs hourly + per-GB processing. Use VPC endpoints for S3/DynamoDB.
Peering vs TGW vs PrivateLinkPeering = 1:1, non-transitive. TGW = hub-and-spoke for an estate. PrivateLink = one service, overlapping CIDRs OK.
How EC2 gets credentialsInstance profile → role → IMDSv2 at 169.254.169.254 → short-lived STS creds, auto-rotated by the SDK.
IAM evaluationExplicit deny wins → SCP ceiling → identity + resource policy → permission boundary → session policy → default deny.
Trust vs permission policyTrust = who can assume the role. Permission = what the session can do.
Multi-AZ vs read replicaMulti-AZ = availability, synchronous, standby not readable. Replica = read scaling, asynchronous, has lag.
Aurora differenceShared distributed storage, 6 copies / 3 AZs, quorum writes; replicas share storage so lag is milliseconds.
DynamoDB hot partitionLow-cardinality or time-based key concentrates traffic → higher-cardinality key or write sharding with a suffix.
LSI vs GSILSI = same PK, different SK, create-time only, strongly consistent. GSI = different PK, add anytime, eventually consistent.
GSI gotchaA throttled GSI can throttle writes to the base table. Project only the attributes you need.
S3 consistencyStrong read-after-write for all ops since Dec 2020. Still no multi-object atomicity.
Big browser uploadPre-signed multipart URLs → direct to S3 → S3 event → SQS → worker. Never proxy the bytes.
S3 hidden costIncomplete multipart uploads and non-current versions. Lifecycle rules for both.
API Gateway REST vs HTTPHTTP API = cheaper, faster, default. REST API = mapping templates, API keys, usage plans, WAF, caching, request validation.
Step FunctionsManaged orchestration: retries with backoff, catch branches, Map/Parallel, and a visible per-execution history.
SagaLocal transactions with semantic compensations. Compensations must be idempotent; do irreversible steps last.
Six W-A pillarsOperational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, Sustainability.
Shared responsibilityAWS secures of the cloud; you secure in the cloud. The line moves right as you go IaaS → serverless.
Top surprise costsEgress + NAT processing, cross-AZ transfer, CloudWatch Logs with no retention, idle/orphaned resources, S3 versions.

Node.js & TypeScript — one-liners

QuestionAnswer in one line
Event loop phasestimers → pending → idle/prepare → poll → check (setImmediate) → close. Microtasks drain between every one.
Microtask orderprocess.nextTick queue drains fully, then the promise queue — after every callback and every phase.
libuv thread poolDefault 4 threads. Used by fs, DNS getaddrinfo, and some crypto — not by network sockets.
Why blocking mattersA 200 ms sync call stalls every concurrent request on that process, not just its own.
CPU-bound workQueue it to a worker; or worker threads with a pool; or chunk with setImmediate. Cluster raises throughput but doesn't unblock a single slow request.
Backpressurewrite() returns false past highWaterMark → wait for 'drain'. Use pipeline(), which also propagates errors and cleans up.
Operational vs programmer errorOperational = handle (retry, 4xx/5xx). Programmer = log and crash; the process state is untrustworthy.
unhandledRejectionLog with context, then exit. Let the orchestrator restart a clean process.
Memory leak suspectsUnbounded Map/cache, per-request listeners on a long-lived emitter, missing backpressure, timers holding objects.
Leak diagnosisTwo heap snapshots under load, diff by retained size, follow the retainer path.
TypeScript's limitTypes are erased at runtime — validate every boundary with zod/io-ts and derive the type from the schema.
unknown vs anyany disables checking and spreads; unknown forces you to narrow before use.
neverBottom type — used for exhaustiveness checks so a new union member becomes a compile error.
AsyncLocalStoragePropagates request context (correlation ID, tenant) through async calls without threading a parameter everywhere.
Resilient HTTP callTimeout + backoff with jitter + idempotency + circuit breaker + bulkhead + keep-alive agent.

Architecture & delivery — one-liners

QuestionAnswer in one line
Service boundary testCan it deploy without coordinating a release with another team? If not, it's one service.
Distributed monolithServices split by technical layer or sharing a database — all the cost of distribution, none of the independence.
Strangler figProxy seam in front of the monolith → extract one capability → shift traffic gradually → delete the old code.
7 RsRetire, Retain, Rehost, Relocate, Replatform, Repurchase, Refactor.
Zero-downtime schema changeExpand → migrate (dual-write + backfill) → contract. Never rename in place.
Cascading failure defencesTimeouts, circuit breakers, bulkheads, backoff with jitter + retry budget, load shedding, graceful degradation.
Observability signalsMetrics (RED/USE), structured logs with correlation IDs, distributed traces. Alert on percentiles, never averages.
Liveness vs readinessLiveness = is the process alive. Readiness = can it serve traffic yet. Both, or deploys drop requests.
Graceful shutdownOn SIGTERM: stop accepting, drain in-flight, deregister from the target group, exit.
Blue/green vs canaryBlue/green = instant rollback, double cost. Canary = best risk control, needs trustworthy metrics + auto-rollback.
Cache stampedeHot key expires, everything misses at once → single-flight lock or probabilistic early expiry.
Terraform stateConfig → real resource IDs. Contains plaintext secrets; needs encryption, locking, versioning; split by blast radius.
DriftReality ≠ code. Detect with scheduled plan; back-port emergency console fixes into code rather than reverting blindly.
Pipeline principleBuild once, promote the same artifact through every environment. Never rebuild per environment.
CI credentialsOIDC federation → short-lived STS role per environment. No long-lived access keys in CI.
Idempotency keyClient-supplied key stored with the response; a retry replays the stored response instead of re-executing.
Cursor vs offset paginationOffset scans and discards rows and shifts under inserts; cursor/keyset is stable and constant-time.

The five sentences to have ready verbatim

1. Opening. "I'm a backend engineer with ~N years, primarily Node.js and TypeScript on AWS, currently owning <services> end-to-end including the pipeline and the alarms."

2. Choosing compute. "I pick by traffic shape and operational appetite: spiky and event-driven → Lambda, steady always-on → Fargate, OS control or licensing → EC2."

3. Event-driven. "Everything is at-least-once, so consumers are idempotent by design — conditional write to a dedup store before the side effect, and the side effect and the dedup record in the same transaction."

4. Opening a design question. "Before I design anything — what's the scale, and what's the latency requirement? And is this greenfield or fitting into an existing estate?"

5. When you don't know. "I haven't run that in production. My working assumption would be X, and I'd verify by checking Y — is that the direction you're thinking?"

Last thing: the round is won on structure, not on knowing more services. Clarify before designing, name the trade-off, quantify where you can, and say "I don't know" cleanly when you don't. That profile passes senior rounds even with gaps; encyclopaedic knowledge delivered as a list does not.
