Logging Platform — Requirements Exercise

Design brief: Design a centralized logging platform that collects, stores, and lets engineers search log events from many services and hosts.

Functional Requirements

  • The system must ingest structured and unstructured log lines from agents on hosts and containers.
  • The system must parse and enrich logs with metadata such as service, host, environment, and severity.
  • Users can perform full-text and field-based searches across logs within a time range.
  • Users can filter logs by tags, severity level, service, and correlation/trace IDs.
  • The system must stream recent logs in near real time ("live tail") for a selected source.
  • Users can create saved searches and define alerts on log patterns or error-rate thresholds.
  • The system must support retention policies with tiered storage and automatic expiration.
  • Users can aggregate logs into counts and trends grouped by fields over time.
  • The system must handle multi-line events such as stack traces as single records.
  • Administrators can control per-team access to log streams and mask sensitive fields.
  • Users can export or archive query results for offline analysis and compliance.

Non-Functional Requirements

  • Ingest 5M+ log events per second, on the order of several terabytes per day at peak.
  • Ingested logs must become searchable within 10 seconds of arrival.
  • Search queries over recent data must return within 2 seconds at p95.
  • Ingestion availability target of 99.95%; the pipeline must buffer and not drop logs during query-tier outages.
  • Retain hot searchable data for 30 days and cold archived data for 1 year.
  • The system must scale horizontally with log volume and number of sources.
  • Logs may be eventually consistent and searchable slightly after ingestion; ordering within a source should be preserved.
  • Sensitive data (PII, secrets, credentials) must be maskable and access must be authenticated and audited.
  • Storage cost must be controlled through compression and movement of older data to cheaper tiers.
  • The system must tolerate bursty traffic spikes of several times the baseline without data loss.

Assumptions & Out of Scope

  • Assume log-shipping agents are already deployed and configured on all hosts.
  • Assume authentication and team/tenant identity come from a central identity provider.
  • Metrics and distributed tracing systems are out of scope; this platform handles log events.
  • Long-term legal archival beyond the stated retention window is excluded.
  • Application-side log formatting and instrumentation standards are owned by service teams.
