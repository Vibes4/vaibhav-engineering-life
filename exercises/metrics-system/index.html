Metrics System — Requirements Exercise

Design brief: Design a time-series metrics platform that collects, stores, and serves numeric measurements emitted by services and infrastructure.

Functional Requirements

  • Clients can emit metrics as timestamped numeric values tagged with dimensions (host, service, region, etc.).
  • The system must support counter, gauge, and histogram metric types.
  • The system must ingest metrics via both push from agents and pull/scrape from targets.
  • Users can query metrics over a time range with filtering and grouping by tags.
  • The system must support aggregation functions such as sum, average, rate, min, max, and percentiles.
  • The system must downsample and roll up older data to coarser resolutions automatically.
  • Users can define alerting rules that evaluate metrics and fire when thresholds are breached.
  • The system must deliver alert notifications to external channels (email, paging, chat).
  • Users can build dashboards composed of multiple metric queries and visualizations.
  • The system must enforce per-metric retention policies.
  • The system must handle late-arriving and out-of-order data points within a bounded window.

Non-Functional Requirements

  • Ingest 10M+ data points per second with millions of active time series.
  • Recent-data queries must return within 500 ms at p95 for typical dashboard time ranges.
  • Ingestion availability target of 99.95%; a brief query outage is more tolerable than dropped ingestion.
  • Store raw data at high resolution for 15 days and downsampled data for 13 months.
  • Alert evaluation latency must stay under 1 minute from data arrival to alert firing.
  • The system must scale horizontally as the number of time series and tags grows.
  • Data may be eventually consistent; brief gaps during ingestion spikes are acceptable.
  • Stored metrics must be durable enough that committed data survives single-node failure.
  • Access to metrics and dashboards must be authenticated and scoped per team or tenant.
  • Storage cost per data point must decrease as data ages via compression and downsampling targets.

Assumptions & Out of Scope

  • Assume metric-emitting agents and client libraries already exist and are instrumented by service owners.
  • Assume identity and tenant management are provided by a central platform.
  • Distributed tracing and log aggregation are out of scope; this system handles numeric metrics only.
  • Long-term archival beyond the stated retention window is excluded.
  • Assume network reachability between agents and ingestion endpoints is already provisioned.
