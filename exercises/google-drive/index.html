Google Drive — Requirements Exercise

Design brief: Design a cloud file-storage and synchronization service that lets users store, sync, share, and collaborate on files and folders across multiple devices.

Functional Requirements

  • Users can upload, download, rename, move, and delete files and folders of arbitrary type.
  • The system must keep a user's files synchronized automatically across all their signed-in devices (desktop, web, mobile).
  • Users can share individual files or folders with other users or via a link, with per-recipient permissions (view, comment, edit).
  • The system must support offline edits on a device and reconcile them once the device reconnects.
  • Users can view and restore previous versions of a file for a defined retention window.
  • The system must support resumable uploads and downloads for large files that survive network interruptions.
  • Users can search their files by name, type, owner, and content (for supported document types).
  • Users can recover deleted files from a trash/bin for a defined period before permanent deletion.
  • The system must show per-user and per-organization storage quota usage and enforce quota limits.
  • Users can star, organize into folders, and see recently accessed and shared-with-me items.
  • The system must generate previews/thumbnails for common file types (images, PDFs, documents, video).
  • The system must record an activity/audit log of changes and shares on a file.

Non-Functional Requirements

  • Support on the order of 1 billion registered users with hundreds of millions of daily active users.
  • Individual file size up to 5 GB (or larger for paid tiers); total stored data at exabyte scale growing tens of PB per day.
  • Sync propagation of a change to other online devices should complete within a few seconds under normal conditions.
  • Metadata operations (list folder, open file) should return within ~200 ms at the 99th percentile.
  • Durability of stored files must be extremely high (target 99.999999999% / eleven nines) with no data loss on device failure.
  • Service availability target of 99.9% or higher for uploads, downloads, and sync.
  • All files must be encrypted in transit and at rest; sharing and access must respect fine-grained authorization.
  • The system must handle read-heavy access patterns with far more reads/syncs than writes.
  • Storage and bandwidth cost per user must be optimized, favoring not re-transferring unchanged data.
  • Concurrent edits and conflicting offline changes must resolve deterministically without silent data loss.

Assumptions & Out of Scope

  • Real-time collaborative document editing (operational transforms in a live editor) is treated as a separate product and out of scope.
  • Assume authentication, account management, and billing are provided by existing platform services.
  • Native desktop/mobile client engineering details are assumed and not designed here.
  • Enterprise admin governance, e-discovery, and DLP policies are out of scope for this exercise.
